# FOGs

Сервер развёртывания образов Windows для компьютерного клуба — замена FOG без
Linux-компонентов и с вменяемым интерфейсом. Рабочее название проекта — FOGs.

Из FOG берём идею «хост → задача → агент», блочное копирование только занятых
кластеров и multicast. Клиенты — Windows в обычном WinPE под UEFI, сервер —
один самодостаточный бинарник на Go.

## Требования к клиентам

Только UEFI x64. Legacy BIOS и режим CSM не поддерживаются и добавляться не будут: сервер таким ПК не отвечает, а образы снимаются только с GPT-дисков. Диск с MBR подходит как цель деплоя, он будет перезаписан в GPT.

## Статус

Проектирование завершено, начат код. Готов пакет [`proto`](proto) — формат образа:
`.ldisk` с полной версией и `.ldelta` только с изменившимися блоками, запись и чтение
цепочек версий. Есть задачи `clone` и `deploy`: агент снимает диск в образ и записывает образ на диск.
В `server/` готовы
сетевая загрузка (proxyDHCP, TFTP, `boot.ipxe`, запуск WinPE) и панель с базой SQLite:
компьютеры и задача запуска агента. Цепочка до экрана агента в WinPE проверена на
реальном ПК. Агент получает задачу от сервера и шлёт прогресс в панель.

Все принятые решения, открытые вопросы и план работ — в
[docs/DESIGN.md](docs/DESIGN.md).

## Сборка и тесты

Go собирается в WSL, на хосте Windows ничего не ставим:

```bash
go vet ./... && go test ./...
```

Кросс-компиляция агента под WinPE:

```bash
GOOS=windows GOARCH=amd64 go build -o bin/partclone.exe ./agent
```

Сервер отдаёт агента из `EFI\agent\partclone.exe`, поэтому собирать удобно сразу туда:

```bash
GOOS=windows GOARCH=amd64 go build -o EFI/agent/partclone.exe ./agent
```

## Экран агента

Агент рисует экран сам и выводит его через Win32. Адрес сервера он берёт из файла
`fogs-agent.json` рядом с собой: сервер подкладывает его при загрузке WinPE. Без этого
файла агент работает на демо-данных, поэтому экран можно смотреть в обычной Windows:

```bash
go build -o bin/partclone.exe ./agent
```

```bash
bin/partclone.exe
```

Клавиши `1`–`5` переключают состояние, `Esc` закрывает окно. Кадры в PNG, без окна:

```bash
FOGS_UI_PREVIEW=каталог go test ./agent/ui -run Previews
```

## Запуск сервера

```bash
go build -o bin/fogs-server.exe ./server
```

Запускать из папки сервера, флаги не нужны:

```bash
bin/fogs-server.exe
```

Панель открывается на том же ПК: <http://127.0.0.1:8081>. Она работает всегда, даже
когда сервер ещё не настроен.

Всё лежит в одной папке, root: это `-root` или папка, из которой запущен сервер.

| Папка | Что в ней |
|---|---|
| `EFI\` | файлы загрузки клиентов, см. ниже. По сети отдаётся только эта папка |
| `data\` | база `fogs.db`, лог `locless.log` и `metrics\` с метриками задач |

Папка образов задаётся в панели и не может лежать внутри `EFI\`.

| Флаг | Значение |
|---|---|
| `-root` | папка сервера, по умолчанию папка запуска |
| `-bind` | адрес для клиентов; без флага он выбирается в панели |
| `-db` | файл базы SQLite, по умолчанию `data\fogs.db`; относительный путь считается от root |
| `-log` | файл лога, по умолчанию `data\locless.log`; старый лог уходит в `.1` после 20 МБ |
| `-admin-addr` | адрес панели, по умолчанию `127.0.0.1:8081`; принимается только loopback |
| `-bootfile` | первый загрузочный файл внутри `EFI\`, по умолчанию `ipxe-shim.efi` |
| `-http-port` | порт HTTP для клиентов, по умолчанию 8080 |
| `-dev` | режим разработки: в панели появляется сценарий замера, см. ниже |
| `-v` | подробный лог |

**Режим настройки.** Службы для клиентов (proxyDHCP на портах 67 и 4011, TFTP и HTTP)
стартуют сами, когда в панели заданы папка образов и адрес для клиентов. Если у машины
один адрес, сервер берёт его сам. Смена адреса применяется без перезапуска сервера, но
прерывает идущие задачи. Если служба упала или порт занят, например CCBoot, она пробует
снова каждые 5 секунд, а панель показывает ошибку.

Службы занимают порты только на адресе для клиентов, а не на `0.0.0.0`: на той же машине
могут работать другой DHCP и TFTP на других адресах. Адреса ПК сервер не выдаёт, это
остаётся за роутером.

`autoexec.ipxe` сервер генерирует сам и отдаёт по TFTP из памяти, класть его в `EFI\`
не нужно. ПК, у которого нет задачи, сразу получает скрипт с одним выходом на диск, без
`dhcp` и HTTP. Сервер узнаёт его по адресу, с которого прошивка спросила порт 4011. Если
это неизвестно, ПК получает полный скрипт: он получает адрес по DHCP и переходит на
`boot.ipxe`, а при любой ошибке уходит на диск. В режиме rEFInd скрипт всегда полный.

### Метрики задач

Агент меряет каждый клон, деплой и форматирование: время этапов, работу внутри них
(чтение, хэш, сжатие, сеть, запись и кто кого ждал), объёмы, процессор, память, диск ПК.
Сервер добавляет свою сторону тех же запросов и время загрузки WinPE. Метрики видны в
панели по кнопке «Метрики» у задачи, а ещё каждая попытка задачи сохраняется файлом
`data\metrics	ask-<id>-attempt-<n>.json`. В файле есть всё, что нужно утилите для
графиков без базы: задача, ПК, образ, итог и сами метрики.

### Сценарий замера (`-dev`)

С флагом `-dev` на странице «Задачи» появляется «Сценарий замера». Выберите тестовый ПК
с образом, и сервер сам поставит задачи по очереди: развёртывание образа на этот ПК,
дельта-клон обратно в тот же образ и полный клон в новый пустой образ
`<образ>-full-<дата>`. ПК проходит их, каждый раз загружаясь по сети. **Диск ПК будет
стёрт.** В конце рядом с метриками появится `scenario-<дата>.json`: какая задача каким
шагом была.

Перед запуском и перед полным клоном сервер проверяет место на диске образов: нужен
размер последней версии образа, ещё 10% и 5 ГБ запаса. Если места нет, сценарий не
начинается или останавливается до создания нового образа. Образ полного клона сервер
не удаляет сам, его можно удалить в панели. Сценарии хранятся в памяти: перезапуск
сервера их забывает, задачи и метрики остаются.

### Переход со старого `-root`

Раньше `-root` был папкой, которая отдаётся по сети, а база и лог лежали в папке запуска.
Теперь это папка сервера. Если сервер запускался как `go run ./server -ip … -root ./EFI/`
из папки проекта:

1. Остановите сервер.
2. Создайте `data\` и перенесите туда `fogs.db`, `fogs.db-wal`, `fogs.db-shm`, а при желании
   и `locless.log`. Пока старая база лежит в корне, а в `data\` её нет, сервер не запустится:
   иначе он начал бы с пустой базы.
3. Файлы загрузки остаются в `EFI\`.
4. Запускайте без `-ip` и `-root`: `go run ./server`. Адрес для клиентов выберите в панели,
   «Настройки → Сеть», или задайте флагом `-bind 192.168.88.254`.

Если файлы загрузки лежат прямо в папке сервера, а не в `EFI\`, сервер пишет об этом в лог,
а панель показывает, каких файлов не хватает.

### Панель

Панель работает без пароля, поэтому сервер открывает её только на loopback: задача
перехватывает загрузку ПК, а клиенты клуба сидят в той же сети. Другой адрес сервер
не примет, пока не появится вход.

- **Настройки → Папка образов:** где хранить образы дисков. Папка не может быть внутри
  `EFI\`: оттуда файлы доступны всем в сети без пароля. Сервер это проверяет.
- **Настройки → Сеть:** адрес, по которому ПК клуба видят сервер, и состояние служб.
- **Обнаружены в сети:** незарегистрированные ПК, загрузившиеся по сети. Сервер им
  не отвечает, а добавляются они в один клик.
- **Компьютеры:** только им сервер отвечает по proxyDHCP. Пока список пуст, сервер
  молчит. В сети с другими ПК добавляйте только тестовые машины.
- **Настройки → Загрузка с диска:** как ПК без задачи уходит из iPXE. По умолчанию `sanboot`:
  iPXE сам находит загрузчик Windows. Есть ещё `exit` и rEFInd (`refind.efi` в каталоге загрузки).
- **Образы:** создайте образ, у него появится папка. Образ без версий можно удалить.
- **Образ компьютера:** выберите в разделе «ПК». Клонирование и развёртывание работают с ним.
- **Клонировать:** загрузите компьютер по сети. Как и FOG, агент удаляет файл подкачки и гибернации,
  сжимает том Windows до размера данных, снимает диск и возвращает том обратно. На сервер идёт только
  то, чего там ещё нет: первый раз получится `v1.ldisk`, дальше `v2.ldelta` и так далее.
- **Развернуть:** подтвердите вторым нажатием. **Диск компьютера будет стёрт.**
  При следующей загрузке по сети агент 20 секунд показывает предупреждение (`Esc` отменяет), затем
  строит таблицу разделов под этот диск, записывает образ и растягивает том на весь диск. Подходит
  внутренний диск с разделом EFI; если такого нет, единственный внутренний или единственный пустой.
  Если выбрать нельзя, деплой остановится. Новый диск и диск с MBR подходят.
- **Проверить связь:** при следующей загрузке по сети ПК запустит WinPE с агентом
  вместо локального диска. Агент дождётся сети, получит задачу, отправит прогресс в
  панель, завершит задачу и перезагрузит ПК, после чего тот грузится с диска. Диск
  при этом не меняется. Если отменить задачу, агент остановится при следующем отчёте.

В `EFI\` для запуска агента должны лежать. Если сервер запущен из папки проекта, первые
три файла уже на месте:

| Файл | Откуда |
|---|---|
| `ipxe-shim.efi` | уже в [EFI/](EFI). Это `x86_64-sb/shimx64.efi` из `ipxeboot.tar.gz` [релиза iPXE](https://github.com/ipxe/ipxe/releases), имя менять нельзя: shim ищет iPXE по своему имени |
| `ipxe.efi` | уже в [EFI/](EFI). Это `x86_64-sb/ipxe.efi` из того же архива: с файлом из другой сборки shim потребует MOK |
| `wimboot` | уже в [EFI/](EFI). Это файл из [релизов wimboot](https://github.com/ipxe/wimboot/releases/latest) |
| `WinPE/boot.wim` | `sources\boot.wim` с ISO Windows, без изменений |
| `agent/partclone.exe` | `go build -o EFI/agent/partclone.exe ./agent` |

Эти файлы, как и всё в `EFI\`, доступны по HTTP без авторизации в `/files/`, поэтому
образы дисков там не храните. Когда агент завершается, WinPE перезагружает ПК.

Что нужно для загрузки клиента:

- файлы `ipxe-shim.efi` и `ipxe.efi` в `EFI\`, см. таблицу выше;
- разрешающее входящее правило брандмауэра Windows для `fogs-server.exe`;
- на клиенте Secure Boot можно не отключать: с этой парой файлов ПК грузится без установки сертификатов и MOK.

На Linux сокет, привязанный к конкретному адресу, не получает broadcast, поэтому
порт 67 там пока не заработает. Проверено только на Windows.

## Референсы

Исходники проектов, у которых заимствуются идеи, подключены как git-сабмодули в
`reference/`. Они нужны как материал для изучения устройства FOG и не входят в
сборку FOGs и не линкуются с нашим кодом.

| Путь | Проект | Upstream | Зачем |
|---|---|---|---|
| `reference/fogproject` | FOG | https://github.com/FOGProject/fogproject | серверная часть, PXE, веб-интерфейс |
| `reference/fos` | FOG OS | https://github.com/FOGProject/fos | bash-агент и мини-Linux на Buildroot |
| `reference/partclone` | partclone | https://github.com/Thomas-Tsai/partclone | формат образа и копирование занятых блоков |

Саблибы зафиксированы на конкретных коммитах, чтобы поведение ссылок не менялось
неожиданно. Лицензии — у исходных проектов, см. `LICENSE` в каждом каталоге.

Клонирование вместе с референсами:

```bash
git clone --recurse-submodules <url> FOGs
```

Если репозиторий уже склонирован без них:

```bash
git submodule update --init --recursive
```

Обновить референсы до свежих версий upstream (осознанно, с проверкой diff):

```bash
git submodule update --remote --merge
```
