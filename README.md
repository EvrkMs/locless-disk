# FOGs

Сервер развёртывания образов Windows для компьютерного клуба — замена FOG без
Linux-компонентов и с вменяемым интерфейсом. Рабочее название проекта — FOGs.

Из FOG берём идею «хост → задача → агент», блочное копирование только занятых
кластеров и multicast. Клиенты — Windows в обычном WinPE под UEFI, сервер —
один самодостаточный бинарник на Go.

## Статус

Проектирование завершено, начат код. Готов пакет [`proto`](proto) — формат образа
с golden-тестами: манифест с таблицей разделов и файл на каждый раздел (заголовок,
bitmap занятых кластеров, независимые нумерованные сжатые чанки). В `server/` готова
сетевая загрузка: proxyDHCP, TFTP и `boot.ipxe`. На реальном клиенте она ещё не
проверялась. Хостов, задач и агента пока нет.

Все принятые решения, открытые вопросы и план работ — в
[docs/DESIGN.md](docs/DESIGN.md).

## Сборка и тесты

Go собирается в WSL, на хосте Windows ничего не ставим:

```bash
go vet ./... && go test ./...
```

Кросс-компиляция агента под WinPE:

```bash
GOOS=windows GOARCH=amd64 go build -o bin/fogs-agent.exe ./agent
```

## Запуск сервера

```bash
go build -o bin/fogs-server.exe ./server
```

```bash
bin/fogs-server.exe -ip 192.168.88.105 -root D:/fogs-tftp -mac-list macs.txt
```

| Флаг | Значение |
|---|---|
| `-ip` | IPv4-адрес сервера в сети клиентов, обязателен; `0.0.0.0` не принимается |
| `-root` | каталог, который отдаётся по TFTP, обязателен |
| `-mac-list` | файл с MAC-адресами, только им сервер отвечает по proxyDHCP |
| `-bootfile` | первый загрузочный файл внутри `-root`, по умолчанию `ipxe.efi` |
| `-http-port` | порт HTTP, по умолчанию 8080 |
| `-v` | подробный лог |

Сервер занимает UDP 67, 69, 4011 и TCP `-http-port` только на адресе `-ip`.
Адреса он не выдаёт, это остаётся за роутером.

### Список MAC

Шаблон лежит в [`server/macs.example.txt`](server/macs.example.txt): один MAC на
строку, после `#` идёт комментарий. Рабочий `macs.txt` в git не попадает.

```text
aa:bb:cc:dd:ee:ff  # тестовый ПК
```

Правки применяются на ходу, перезапускать сервер не нужно. Если при запуске файла
нет или в нём ошибка, сервер не стартует. Если ошибка появилась при работе, остаётся
предыдущий список, а в логе будет номер строки. Удалённый файл означает пустой список.

**С пустым списком сервер никому не отвечает**, а только пишет в лог MAC обнаруженных
PXE-клиентов: так удобно узнать MAC нового ПК. В сети с другими ПК вносите только
тестовые машины, иначе их загрузка уйдёт на этот сервер.

Что нужно для загрузки клиента:

- файл `ipxe.efi` в `-root` (в репозитории его нет);
- разрешающее входящее правило брандмауэра Windows для `fogs-server.exe`;
- отключённый Secure Boot на клиенте, пока не выбран путь из §12 `DESIGN.md`.

На Linux сокет, привязанный к конкретному адресу, не получает broadcast, поэтому
порт 67 там пока не заработает. Проверено только на Windows.

## Референсы

Исходники проектов, у которых заимствуются идеи, подключены как git-сабмодули в
`reference/`. Они нужны как материал для изучения устройства FOG и не входят в
сборку FOGs и не линкуются с нашим кодом.

| Путь | Проект | Upstream | Зачем |
|---|---|---|---|
| `reference/fogproject` | FOG | https://github.com/FOGProject/fogproject | серверная часть, PXE, веб-интерфейс |
| `reference/fos` | FOG OS | https://github.com/FOGProject/fos | bash-агент и мини-Linux на Buildroot |
| `reference/partclone` | partclone | https://github.com/Thomas-Tsai/partclone | формат образа и копирование занятых блоков |

Саблибы зафиксированы на конкретных коммитах, чтобы поведение ссылок не менялось
неожиданно. Лицензии — у исходных проектов, см. `LICENSE` в каждом каталоге.

Клонирование вместе с референсами:

```bash
git clone --recurse-submodules <url> FOGs
```

Если репозиторий уже склонирован без них:

```bash
git submodule update --init --recursive
```

Обновить референсы до свежих версий upstream (осознанно, с проверкой diff):

```bash
git submodule update --remote --merge
```
