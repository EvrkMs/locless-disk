# FOGs

Сервер развёртывания образов Windows для компьютерного клуба — замена FOG без
Linux-компонентов и с вменяемым интерфейсом. Рабочее название проекта — FOGs.

Из FOG берём идею «хост → задача → агент», блочное копирование только занятых
кластеров и multicast. Клиенты — Windows в обычном WinPE под UEFI, сервер —
один самодостаточный бинарник на Go.

## Требования к клиентам

Только UEFI x64. Legacy BIOS и режим CSM не поддерживаются и добавляться не будут: сервер таким ПК не отвечает, а образы снимаются только с GPT-дисков. Диск с MBR подходит как цель деплоя, он будет перезаписан в GPT.

## Статус

Проектирование завершено, начат код. Готов пакет [`proto`](proto) — формат образа:
`.ldisk` с полной версией и `.ldelta` только с изменившимися блоками, запись и чтение
цепочек версий. Есть задачи `clone` и `deploy`: агент снимает диск в образ и записывает образ на диск.
В `server/` готовы
сетевая загрузка (proxyDHCP, TFTP, `boot.ipxe`, запуск WinPE) и панель с базой SQLite:
компьютеры и задача запуска агента. Цепочка до экрана агента в WinPE проверена на
реальном ПК. Агент получает задачу от сервера и шлёт прогресс в панель.

Все принятые решения, открытые вопросы и план работ — в
[docs/DESIGN.md](docs/DESIGN.md).

## Сборка и тесты

Go собирается в WSL, на хосте Windows ничего не ставим:

```bash
go vet ./... && go test ./...
```

Кросс-компиляция агента под WinPE:

```bash
GOOS=windows GOARCH=amd64 go build -o bin/fogs-agent.exe ./agent
```

## Экран агента

Агент рисует экран сам и выводит его через Win32. Адрес сервера он берёт из файла
`fogs-agent.json` рядом с собой: сервер подкладывает его при загрузке WinPE. Без этого
файла агент работает на демо-данных, поэтому экран можно смотреть в обычной Windows:

```bash
go build -o bin/fogs-agent.exe ./agent
```

```bash
bin/fogs-agent.exe
```

Клавиши `1`–`5` переключают состояние, `Esc` закрывает окно. Кадры в PNG, без окна:

```bash
FOGS_UI_PREVIEW=каталог go test ./agent/ui -run Previews
```

## Запуск сервера

```bash
go build -o bin/fogs-server.exe ./server
```

```bash
bin/fogs-server.exe -ip 192.168.88.105 -root D:/fogs-tftp
```

Панель открывается на том же ПК: <http://127.0.0.1:8081>.

| Флаг | Значение |
|---|---|
| `-ip` | IPv4-адрес сервера в сети клиентов, обязателен; `0.0.0.0` не принимается |
| `-root` | каталог, который отдаётся по TFTP и HTTP, обязателен |
| `-db` | файл базы SQLite, по умолчанию `fogs.db` |
| `-log` | файл лога, по умолчанию `locless.log`; старый лог уходит в `.1` после 20 МБ |
| `-admin-addr` | адрес панели, по умолчанию `127.0.0.1:8081`; принимается только loopback |
| `-bootfile` | первый загрузочный файл внутри `-root`, по умолчанию `ipxe.efi` |
| `-http-port` | порт HTTP для клиентов, по умолчанию 8080 |
| `-v` | подробный лог |

Сервер занимает UDP 67, 69, 4011 и TCP `-http-port` только на адресе `-ip`.
Адреса он не выдаёт, это остаётся за роутером.

`autoexec.ipxe` сервер генерирует сам из `-ip` и `-http-port` и отдаёт по TFTP из
памяти. Класть его в `-root` не нужно, файл с таким именем там будет проигнорирован.
Скрипт получает адрес по DHCP и переходит на `boot.ipxe`, а при любой ошибке
возвращает ПК в UEFI, и тот грузится с диска.

### Панель

Панель работает без пароля, поэтому сервер открывает её только на loopback: задача
перехватывает загрузку ПК, а клиенты клуба сидят в той же сети. Другой адрес сервер
не примет, пока не появится вход.

- **Настройки → Папка образов:** где хранить образы дисков. Папка не может быть внутри
  `-root`: оттуда файлы доступны всем в сети без пароля. Сервер это проверяет.
- **Обнаружены в сети:** незарегистрированные ПК, загрузившиеся по сети. Сервер им
  не отвечает, а добавляются они в один клик.
- **Компьютеры:** только им сервер отвечает по proxyDHCP. Пока список пуст, сервер
  молчит. В сети с другими ПК добавляйте только тестовые машины.
- **Настройки → Загрузка с диска:** как ПК без задачи уходит из iPXE. По умолчанию `sanboot`:
  iPXE сам находит загрузчик Windows. Есть ещё `exit` и rEFInd (`refind.efi` в каталоге загрузки).
- **Образы:** создайте образ, у него появится папка. Образ без версий можно удалить.
- **Образ компьютера:** выберите в разделе «ПК». Клонирование и развёртывание работают с ним.
- **Клонировать:** загрузите компьютер по сети. Как и FOG, агент удаляет файл подкачки и гибернации,
  сжимает том Windows до размера данных, снимает диск и возвращает том обратно. На сервер идёт только
  то, чего там ещё нет: первый раз получится `v1.ldisk`, дальше `v2.ldelta` и так далее.
- **Развернуть:** подтвердите вторым нажатием. **Диск компьютера будет стёрт.**
  При следующей загрузке по сети агент 20 секунд показывает предупреждение (`Esc` отменяет), затем
  строит таблицу разделов под этот диск, записывает образ и растягивает том на весь диск. Подходит
  внутренний GPT-диск с разделом EFI, куда помещаются данные образа: сетевые диски, USB и диски без
  такой разметки агент не трогает.
- **Проверить связь:** при следующей загрузке по сети ПК запустит WinPE с агентом
  вместо локального диска. Агент дождётся сети, получит задачу, отправит прогресс в
  панель, завершит задачу и перезагрузит ПК, после чего тот грузится с диска. Диск
  при этом не меняется. Если отменить задачу, агент остановится при следующем отчёте.

В `-root` для запуска агента должны лежать:

| Файл | Откуда |
|---|---|
| `wimboot` | [релизы wimboot](https://github.com/ipxe/wimboot/releases/latest) |
| `WinPE/boot.wim` | `sources\boot.wim` с ISO Windows, без изменений |
| `agent/fogs-agent.exe` | `go build -o D:/fogs-tftp/agent/fogs-agent.exe ./agent` |

Эти файлы, как и всё в `-root`, доступны по HTTP без авторизации в `/files/`, поэтому
образы дисков там не храните. Когда агент завершается, WinPE перезагружает ПК.

Что нужно для загрузки клиента:

- файл `ipxe.efi` в `-root` (в репозитории его нет);
- разрешающее входящее правило брандмауэра Windows для `fogs-server.exe`;
- отключённый Secure Boot на клиенте, пока не выбран путь из §12 `DESIGN.md`.

На Linux сокет, привязанный к конкретному адресу, не получает broadcast, поэтому
порт 67 там пока не заработает. Проверено только на Windows.

## Референсы

Исходники проектов, у которых заимствуются идеи, подключены как git-сабмодули в
`reference/`. Они нужны как материал для изучения устройства FOG и не входят в
сборку FOGs и не линкуются с нашим кодом.

| Путь | Проект | Upstream | Зачем |
|---|---|---|---|
| `reference/fogproject` | FOG | https://github.com/FOGProject/fogproject | серверная часть, PXE, веб-интерфейс |
| `reference/fos` | FOG OS | https://github.com/FOGProject/fos | bash-агент и мини-Linux на Buildroot |
| `reference/partclone` | partclone | https://github.com/Thomas-Tsai/partclone | формат образа и копирование занятых блоков |

Саблибы зафиксированы на конкретных коммитах, чтобы поведение ссылок не менялось
неожиданно. Лицензии — у исходных проектов, см. `LICENSE` в каждом каталоге.

Клонирование вместе с референсами:

```bash
git clone --recurse-submodules <url> FOGs
```

Если репозиторий уже склонирован без них:

```bash
git submodule update --init --recursive
```

Обновить референсы до свежих версий upstream (осознанно, с проверкой diff):

```bash
git submodule update --remote --merge
```
